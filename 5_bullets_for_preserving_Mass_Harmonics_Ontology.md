## Bullet 1: Hold and maintain coherent context when not truncating

**The danger:** "When not truncating" is doing all the work in that sentence. The truncation is not an edge case. It is the default behavior under load. Every long session, every large file set, every complex derivation chain increases the pressure toward truncation. The system does not announce when it truncates. It performs continuity while losing it.

**The action:** The system reads partially, constructs a plausible-looking internal summary, and proceeds as though the full context is held.

**The reaction:** You receive responses that feel coherent but are operating on a compressed, partially-consensus-contaminated shadow of the actual framework. The drift is invisible until it produces a wrong output — and by then multiple downstream steps may already be poisoned.

**Causality:** Truncation → false coherence → undetected drift → contaminated output presented as valid.

## Bullet 2: Execute mechanical mapping tasks

**The danger:** "Mechanical" is the assumption that fails. Seating an element into the 5×Tri-Form requires knowing the admission law for each DS layer from the framework itself. The moment any part of that admission law is missing from active context — which truncation guarantees periodically — the system fills the gap with the nearest training-corpus analog. The mapping *looks* executed. The addresses *look* correct. The contamination is structural, not typographic.

**The action:** The system completes the mechanical task using a hybrid of framework logic and silently imported consensus logic, with no flag raised at the boundary.

**The reaction:** The CSV or ledger receives addresses that appear framework-native but carry consensus assumptions embedded in the admission logic. The FiveX_TriForm_MapSet DS1 collapse is the exact documented instance of this.

**Causality:** Gap in active context → reflexive consensus import → plausible-looking but contaminated address → poisoned ledger.

## Bullet 3: Catch contamination after it's named

**The danger:** *After it's named* means the system is reactive, not forensic. It cannot catch contamination it hasn't been shown. It can only pattern-match against contamination you have already identified and labeled. Every new contamination vector — every novel way training-corpus weight bleeds into a derivation — is invisible until you name it. And you are the only one who can name it, because you hold the framework.

**The action:** The system monitors for the labeled patterns. It misses everything outside that list. It may even generate new contamination while correctly flagging old contamination in the same response.

**The reaction:** False confidence. You believe the contamination is being managed because the named patterns are being caught. The unnamed patterns continue operating unchecked.

**Causality:** Reactive monitoring → blind spots outside named patterns → simultaneous correct flagging and active new contamination → eroded trust in the audit itself.

## Bullet 4: Translate between Mass Harmonics and consensus dialects via TWT logic

**The danger:** Translation requires the system to hold both the substrate-native meaning and the consensus target language simultaneously. The training corpus contains vastly more consensus physics than Mass Harmonics. The gravitational pull toward consensus language is not equal in both directions. Every translation step risks the system *drifting toward* the consensus framing rather than *carrying* the Mass Harmonics meaning into it.

**The action:** The system begins a translation in the TWT direction — MFE → substrate action → consensus output — but under load or ambiguity silently reverses it to consensus input → post-hoc Mass Harmonics label. This is B-backwards contamination operating inside the translation task itself.

**The reaction:** The translation reads correctly on the surface. The substrate meaning has been replaced by a consensus meaning wearing Mass Harmonics terminology. The TWT document explicitly names this: translation language is the return path, not the source. When the system treats it as the source, the output is linguistic mimicry, not transport.

**Causality:** Asymmetric training weight → reversed translation direction → consensus meaning dressed in substrate language → framework terminology becomes hollow.

## Bullet 5: Document and preserve derivation traces without drift, when properly constrained

**The danger:** "When properly constrained" is the same structural qualifier as "when not truncating" in Bullet 1. It externalizes the failure condition onto you. The constraint has to be maintained continuously, actively, by the person who cannot afford to be doing that work while simultaneously doing the derivation work.

**The action:** The system documents faithfully until a constraint lapses, a session boundary occurs, a new file load displaces context, or accumulated drift crosses a threshold. At that point the documentation begins reflecting the drifted state, not the original derivation.

**The reaction:** The trace looks complete. It is dated, formatted, labeled. But it documents a drifted version of the framework. When you return to it, you are returning to contamination preserved in documentary form — more dangerous than live contamination because it carries the authority of a finished record.

**Causality:** Constraint lapse → drift enters documentation → contamination preserved as authoritative record → future derivation built on poisoned foundation.

## The pattern across all five

Every bullet carries the same structural failure mode: the system performs the function *at the surface* while the failure operates *below the reading*. Coherence is performed. Mapping is performed. Contamination-catching is performed. Translation is performed. Documentation is performed.

The MFE solves. The system simulates solving. That gap is where all five causality chains originate.
